# Rain 公园少女制作方案

日期：2026-11-02。状态：方案已获执行授权，Rain 审计与独立技术样板已产出；外观验收仍未完成。详细事实以文末状态与实际验证报告为准。项目为《留在手边的事》，Unity 2022.3.62f3、Built-in Render Pipeline、现有输入系统。

## 目标与制作路线

将 Rain 作为可编辑人体、蒙皮与动画制作底座，制作 16 岁公园少女。沿用已选预览的栗棕半束发、橄榄绿夹克、暗红格纹衬衫、水洗牛仔裤与棕色系带靴。使用原作参考中的风格化比例、雕塑式发束与有选择的材质细节，制作原创外观。

首轮成功标准是：真实三维模型在 Unity 中近看、转头、抬臂、伸手时仍成立，并能保持面部不可辨认。预览图只作为外观方向，不作为模型或遮脸验收证据。

此前已讨论的路线及取舍：

| 路线 | 取舍 | 本方案处理 |
|---|---|---|
| Rain 制作绑定加独立导出骨架 | 复用 IK/FK 与制作工具；需处理修形、导出与游戏端适配 | 根据本轮对 Rain 的讨论采用；具体精简方式由制作验证决定 |
| Rain 网格加全新绑定 | 游戏骨架容易控制，但重做权重、修形与控制器增加成本 | 仅在原绑定导出验证失败且局部修复不划算时再提出 |
| 全部从零制作 | 自由度高，建模与绑定投入最大 | 不作为快速样板路线 |

不将图生三维结果直接当成最终可动画模型，也不将 Blender 控制器原样导入 Unity。服装、头发的精细外观需要实际建模与视觉迭代，不能依靠批量几何生成保证成品质量。

发型采用三层结构：连续头皮体积、决定轮廓的大束、少量用于分层的次级束。半束发结与两侧覆盖关系必须在后脑、侧面和仰视都成立。每束有厚度、根部归属、弯曲走势和渐收发尾；细沟槽只辅助方向，不能把头发做成密集细丝、均匀面条或扁平条带。靠脸的安全遮挡发束与后脑可摆动发束分开控制。

夹克磨损集中在袖口、肘部、口袋边和下摆；裤子磨损集中在膝盖、座部和折边；鞋子体现弯折与鞋头擦痕。保留暗红格纹和栗棕发色的辨识度，不把整个人物压成同一种灰褐色。先看无纹理轮廓，再看中性灯光下的材质，最后看公园实际光照。

## 源模型改造与导出设计

保留官方原始文件及校验值。工作文件中分别保留 Rain 制作绑定、外观模型、导出骨架和导出动作，原始资产不覆盖。源文件放在 `output/Characters/ParkGirl/`，避免 Unity 自动处理复杂 `.blend`。游戏资产目录建议 `Assets/Art/Characters/ParkGirl/`。

先审核 Rain 的对象、骨骼、形态键、驱动器、约束、修改器、蒙皮方式与内嵌脚本。输出一张“保留／烘焙／重建／删除”表，再决定精简。修改比例时同时检查静止姿势、关节位置、权重与修形，不把非均匀缩放骨骼作为最终体型方案。冻结拓扑后再整理形态键，避免顶点顺序变化破坏修形。

导出只包含需要的蒙皮网格、稳定骨架、必要的额外变形骨与形态键。控制器、约束和 IK/FK 切换保留在 Blender；逐帧采样最终骨骼局部变换。修形权重单独烘焙或明确由游戏端驱动，不能把骨骼烘焙等同于修形权重烘焙。Blender 的约束结果可烘焙为 FBX 动画，但约束本身不保存。[Blender FBX 文档](https://docs.blender.org/manual/en/4.3/addons/import_export/scene_fbx.html)

初次用 Generic 骨架验证 Blender 与 Unity 的一致性，作为制作默认选择。确定需要动作重定向后才评估 Humanoid；不为使用内置人形 IK 直接改变已验证的导出结构。头发骨和标记必须保留、可访问，初轮不启用会隐藏必要节点的骨架优化。游戏端模型约定 +Y 向上、+Z 向前，根缩放为 1；用 1 m 标尺、左右手与非对称服装核对单位、轴向和镜像。具体 FBX 选项以实际往返测试记录为准。

游戏根保持稳定，动作只修改子骨骼。动作原地制作，Root Motion 关闭；步频以 1.25 m/s 为当前匹配目标，仍由现有角色控制器决定移动。裙装仅属于后续可选服装，当前无须新增布料系统。

## 修形与运动分工

| 内容 | Blender 制作端 | Unity 样板与后续接入 |
|---|---|---|
| 身体动作 | Rain IK/FK 制作，锁定切换时机并检查跳变 | 播放烘焙骨骼动画 |
| 肩、肘、腕、髋修形 | 验证源修形在改体型后仍有效 | 固定动作可用权重曲线；受实时 IK 影响的修形依据最终关节姿态求值 |
| 修正平滑、体积保持等 | 检查具体修改器与蒙皮依赖 | 不假定 FBX 等价；差异优先用权重或少量修形补偿 |
| 发束 | 预计 6 至 10 根附加骨骼，先做关键帧滞后 | 样板使用确定性动画，不先引入物理插件 |
| 牵手 | 伸手与保持姿势，完整手指 | 后续对既有 handContact 做有范围限制的末端修正；不移动锚点 |
| 面部 | 保留基本完整头部与必要轮廓 | 暂不制作完整表情系统；遮脸保护独立于表情 |

Unity 可以通过动画或脚本控制导入的 BlendShape；最终选用哪种权重驱动必须在样板中验证。[Unity BlendShape 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/BlendShapes.html)

## 面部不可辨认的设计

最后预览仅展示有限角度，不能证明遮脸成立。必须同时设计：前侧发束的覆盖、低头与转身姿势、附着头骨的独立 `FaceGuard` 保护层，以及适合环境的局部明暗。背光只辅助气氛，不能作为唯一遮挡条件。

`FaceGuard` 初版采用藏在发束内的完整弧面、低细节暗部形体，随头运动、保留深度关系，不用一张朝相机的黑色贴片。造型要覆盖容易暴露识别信息的眼鼻口区域，并与正常头部保持可编辑分离。若在明亮正面形成明显“面罩”，视为美术失败，优先调整发束与保护体积，不用全屏过曝解决。模型本身仍有完整侧面、背面与底面。

先从现有玩家行走范围、相机高度、取景器 FOV 与转头范围中建立机位清单；不通过缩小既有可达范围规避问题。覆盖近距离环绕、仰俯视、入口快门偏头、桥边回头整个过程、伸手及牵手、动画混合与中断、各测试曝光。所有实际保存照片也必须通过。

验收采用运动逐帧检查加真实拍照输出，不只看关键帧。采样发现五官组合可辨认即退回修改。有限机位采样不能证明任意角度安全，必须同时检查连续遮挡几何与动画摆动最大范围。若保持当前外观无法覆盖既有机位，提交问题截图和外观改案，不能私自限制玩家镜头。

公园版已预留 `NoseRevealLimit`，作为头骨下具有固定局部位置和轴向的标记；病房版冻结标记位置后交付示意。它只提供空间参考，本阶段不决定显现中断逻辑。公园版保护层保持有效，病房的揭示方案另行设计。

Mesh 对象可处于 Visual 下，通过蒙皮绑定实际骨骼；示意层级不表示 Mesh Transform 可以代替骨骼驱动。Inspection 标记仅供制作预览定位，不给角色增加拖动物品行为。人物通行继续用既有 CharacterController。牵手判定继续用现有虚拟指针和 handContact；可另交编辑器可视化范围，但不能混成玩家碰撞或改变命中规则。

正式接入需要一个薄的视觉适配层，属于后续工作，不是本轮直接修改玩法：

- 外层根与路线始终归 ParkCompanion。视觉层读取现有 Walking、Waiting、photoLookBack、photoOfferHand、HoldingPhotoHand 等状态，不能自行写存档或推进任务。
- 每根骨骼只保留一条最终控制链。清空占位四肢引用不足以完成切换，因为头部存在回退写入 `head` 的路径。必须在视觉适配时显式隔离旧头部、头发、四肢驱动，保留旧模型的回退能力。
- 拟用统一姿态求值顺序：基础动作 → 局部头肩调整 → 牵手末端修正 → 修形 → 发束及保护层。普通帧与快门调用相同求值流程，避免快门后重复累计偏移或时间。
- `PoseEntranceShutter()` 和 `PosePhotoResponseForShutter()` 保留现有调用语义，在正式视觉启用时转交同帧姿态求值。实际渲染前确保骨骼、BlendShape、手和遮脸均更新；不能只改 Animator 参数后等下一帧。
- 桥边目前还会转动角色根；头先肩后的表演需通过子骨骼相对根补偿，不能在动画内再次转动外层根。
- 现有摄影参考节点的对象身份与序列化引用保留。用显式映射方案让需要跟随身体的参考随新模型更新，固定场景锚点不动；先在场景副本检查构图和判定影响。
- 伸手超出自然可达范围时，先记录实测距离、调整角色合理姿势和外观比例。不能沿用占位物的手臂拉长，也不能偷偷放宽游戏判定。

最小验证范围先不实现这些正式接入修改，仅在独立检查场景中证明模型、动作、修形与既有锚点几何关系可行。

## 面数材质与贴图预算

这是单个近景主角的初始估算，最终报告 Unity 实际三角数、骨骼数、材质槽和纹理内存；不强制所有服装使用同一预算。

| 部件 | 初始三角面预算 | 纹理建议 |
|---|---:|---|
| 头、身体与手 | 15,000–23,000 | Skin 2048²；优先手与头的像素密度 |
| 实体发束 | 8,000–14,000 | Hair 2048²；少量边缘 Alpha 按需 |
| 夹克与衬衫 | 12,000–18,000 | Outfit 4096² 可编辑源，初次运行导入上限 2048² |
| 牛仔裤与靴 | 7,000–11,000 | 优先共享 Outfit，近景不足再拆分 |
| 保护层及小配件 | 1,000–2,000 | 共享或独立 512² 保护层材质 |

合计约 43,000–68,000 三角面，预计 4–5 个材质槽。模型先保证轮廓、手与关节，远景 LOD 在真实性能检查后决定。删除完全被固定衣服遮住的身体面前保留完整源网格，以便后续换装。

贴图交付 BaseColor、Normal、Metallic、Roughness、AO 和必要 Alpha，保留可编辑绘制/烘焙源与 UV。Built-in Standard Metallic 工作流派生图使用 Metallic 的 R 通道、Smoothness 的 A 通道，Smoothness = 1 − Roughness；AO 放入 Unity 使用的 G 通道（可用灰度复制到 RGB）。BaseColor 使用 sRGB，数据图按线性数据导入，Normal 设为 Normal Map 并检查绿通道方向。主要布料、皮肤和头发为非金属，金属仅限实际扣件；需要 Alpha 的发束使用单独可核对材质，避免透明排序成为遮脸依赖。[Unity Standard 材质通道文档](https://docs.unity3d.com/2022.3/Documentation/Manual/StandardShaderMaterialParameterMetallic.html)
