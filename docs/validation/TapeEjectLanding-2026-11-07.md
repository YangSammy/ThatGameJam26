# 磁带弹出后落到盒底：调查与修复

## 根因与证据

- 工作带弹出回调首先尝试准备垫，失败后调用 `ReturnTapeToDesk`。
- 春季场景的 B1/B2 备用落点与收纳盒 X/Z 范围重叠。盒底没有实心物理碰撞体，`OperationArea.Place` 只检查碰撞，因而接受并保存盒底下的位置。
- 使用春季场景数据，在编辑模式隔离加载、模拟运行时关闭行走专用碰撞体后验证：准备垫空闲时五盘工作带均可放置；B1/B2 原备用落点均出现 `placed=True, overlapsBox=True`，高度约 0.8047，而盒底中心高度约 0.82。
- 初次编辑模式探测的放置失败由尚未执行运行时关闭逻辑的 `Desk_Walking_collision` 引起；对齐真实运行时条件后排除该假设，未修改导航碰撞逻辑。

## 修复

仅修改 `HouseRadioDeck.Storage.cs`：备用落点先经过操作区边界约束，再显式排除盒体占地范围，最后进行原有碰撞检查与位置保存。首选落点不可用时，按距离搜索当前操作区的空位。已有磁带不移动。若整个操作区无可用落点，保留原来的盒内槽位并打开盒盖，不提交盒底位置。

## 验证

- Unity 2022.3.62f3 脚本编译无错误。
- 在春季场景数据中让一盘工作带占据准备垫，其余四盘连续返回桌面：均不与盒体占地重叠，均生成稳定位置记录，准备垫已有磁带不移动。
- 三盘原带返回桌面通过；保存落点恢复通过。
- 临时加载的场景已关闭，未保存场景、Prefab 或玩家存档。
- 验证覆盖实际落点函数及物理查询，没有启动完整 Play Mode 重走录音/弹出动画。测试代码与修改前快照见 `output/validation/tape-eject-20261107/`。
