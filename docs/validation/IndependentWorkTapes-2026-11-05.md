# 独立工作磁带流程实施与验证

日期：2026-11-05。Unity 2022.3.62f3；当前工作区直接实施，未提交或推送。

## 已实施

- 五盘工作带：原有两盘坏带，三盘独立好带；三盘源带保持原身份。
- 每盘独立保存双轴扫描、两孔贴纸、位置和成品归属。下一份委托不会清空其他磁带的准备状态。
- 开始录音前保存录音与磁带身份的关联。退带后可以重装同一盘；有录音时不能换空带继承。R 重试清当前录音，保留这盘的检查和封孔。
- 验收并成功提交存档后，同一盘磁带进入对应成品位，B 槽清空；成品不可重新装载、准备或录音。旧装饰副本隐藏。
- 新盘必须重新检查双轴、封两孔。现有 A/B 切换控制、音效和噪声验收规则保留。
- 场景增加两盘磁带、各自桌面落点、三个成品位；收纳近景调整，五盘可分别命中。
- 版本 9 检查点；旧版已交付副本分配到新增好带，保留原好带的未完成工作。PCM 格式、内容及源音频哈希不改写。
- 录到一半取出并撕掉贴纸仍可正常读档，补齐双孔后才能继续录音/提交。旧版录音也按原带稳定 ID 恢复归属。

## 实际验证

- Unity 编译通过；Console 错误数为 0。
- `IndependentTapeModelChecks.Run()`：五盘模型、分离提交不修改现场、三份独立归档、其他带准备保留、身份重排、旧版迁移、损坏存档拒绝、录音带撕贴纸后恢复、旧版未封孔录音恢复通过。原五盘数量与撕贴纸问题均有修复前失败记录。
- `V3TapeContractChecks.Acceptance()`：16 项通过，保留原噪声/内容验收及边界宽容度。
- `IndependentTapeRuntimeChecks.StorageGeometry()`：6 项通过，含五盘磁带从打开盒子的实际近景相机分别命中。
- `TapeToggleStorageChecks.Storage/Transport/RestoreAndSubmit()`：收纳取出、原 A/B 独立控制、真实 PCM 保存重载、第一份提交通过。
- `IndependentTapeRuntimeChecks.RemainingCopies()`：40 项通过。真实音频回调与控制器依次完成第二、第三份；未检查/单孔不能录；失败不归档；换带不能继承录音；重试保留准备；相同场景物件进入对应成品位；第一份 PCM 字节保持一致；重置不把成品送回盒内。
- 完整退出并重启 Play，进入夏季后返回春季：三盘成品位置、已完成章节、空 B 槽恢复通过。
- 两盘新增磁带分别从盒内移至桌面，经 OperationArea 碰撞/放置校验并持久化通过。
- 已查看五盘收纳及三盘成品的实际相机渲染。独立代码审查发现的录音带贴纸移除存档问题已修复并加入检查。
